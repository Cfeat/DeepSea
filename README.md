# 深海 · Deep Sea

面向中文读者的海洋科普网站，使用 React 19、TypeScript 和 Vite。线上地址：[深海](https://www.cfeat.cc.cd/DeepSea/)。

## 本地运行

```sh
npm ci
npm run dev
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Vite 的默认地址是 `http://localhost:5173/DeepSea/`。浏览器回归测试启动独立的生产预览服务，使用 5176 端口。GitHub Actions 在数据测试、构建和浏览器测试通过后发布 GitHub Pages。

## 页面与数据

- 首页、深度探索、生物图鉴、深海实验室、海洋专题、深海游乐场、参考资料分别独立渲染。固定导航标出当前页面，手机端提供可用 Esc 关闭的菜单；面包屑、页面标题和浏览器前进后退保持同步。
- 使用 hash 路由兼容 GitHub Pages 的静态部署：`#home`、`#journey`、`#atlas`、`#lab`、`#topics`、`#games`、`#sources`。专题详情使用 `#topics/<id>`，两款游戏分别使用 `#games/story` 和 `#games/station`，刷新和直接访问不需要服务器回退规则；此前的锚点入口仍有效。
- 垂直深度轴是主要体验，保留滚动下潜、左右交替的生物卡片、深度和压力读数、海层跳转。
- 浅水区按卡片所需空间展开，稀疏区压缩空白；海洋雪、热液喷口、鲸落、海底地形、海沟和深度测量构成六个科普停留点，并链接到各自的独立专题。
- 图鉴每页 12 个条目，可搜索中文名、英文名、学名和特征，支持收藏与跳回深度轴。切换页面保留当前筛选，改变筛选回到第一页。百科链接使用 `?creature=<id>#atlas`，旧的无 hash 链接仍能直接打开对应条目。
- 收藏、已读记录和下潜位置保存在当前浏览器。存储被禁用或数据损坏时，仍可阅读；“继续上次下潜”由读者主动选择。
- 实验室包含海水压力估算、柔软密闭气囊的玻意耳定律示范、从下方观察的反照明示范。计算条件放在折叠说明中。
- 原生 dialog 支持 Esc、焦点约束、关闭后焦点和滚动位置恢复。界面适配手机和减少动态效果偏好。

`src/App.tsx` 管理页面、筛选、收藏和条目链接；`utils/navigation.ts` 定义入口与 URL 解析；各页面组件独立，功能页面和百科按需加载，加载失败由 `PageBoundary` 提供恢复入口。`components/DiveExplorer.tsx` 管理轴上交互；`utils/diveLayout.ts` 是海层、刻度、跳转和读数共用的双向坐标映射。该轴明确为非等比例的阅读轴，所有条目均保留，相同深度条目堆叠排列。

`data/creatureData.ts` 汇总 49 个物种或类群条目，本次新增条目放在 `data/expandedCreatures.ts`。`data/types.ts` 定义科学资料结构，`data/media.ts` 与 `data/expandedMedia.ts` 保存已核对的生物图片出处、图片文件 URL、署名和许可。`data/topics.ts` 管理科普停留点和专题文章，`data/topicMedia.ts` 管理环境照片与测深数据图；`data/science.ts` 管理压力、气体体积模型和通用资料。

## 深海游乐场

- **深渊来信**：独立的文字探险。六章调查、六种可达结局、两档难度、四件装备中选择两件，管理船体、氧气、电量和队员信任。装备、救援、观测和返航决定影响报告；航行笔记保存观察与完整选择日志。
- **深海前哨**：独立的回合经营游戏。12 个相邻建造位置、8 种可建舱室、三级升级、人员调配与招募、6 类资源、5 项科技、3 类可重复考察和 4 种站点事件。每天结算生产、维护、供给和任务，支持暂停设备、拆除、维修和补给。30 天内通过长期站点评估即可通关，随后可继续自由经营；连续短缺、结构损坏或士气耗尽会触发撤离。
- 两款游戏各有独立、带版本的浏览器存档，可导出 JSON 并在其他设备导入。导入前确认替换，仅替换当前游戏。存档记录初始设置和操作序列，读取时通过规则重新演算，不直接信任导入的资源或结局；损坏、错误游戏和无效操作不会覆盖现有进度。浏览器存储不可用时仍可游玩、导出。
- `games/storyEngine.ts` 与 `games/stationEngine.ts` 是不依赖 React 的规则模块，`games/useGameSave.ts` 管理存档，`components/games` 管理独立页面和操作。游戏代码只在进入对应游戏时加载。
- 人物、站点、装备消耗和经营数值属于虚构游戏规则。游戏中的生物和环境可打开真实百科或专题阅读，阅读不消耗资源。

内容组织参考 [Smithsonian Ocean](https://ocean.si.edu/) 的主题分类、快捷入口，以及 [NOAA Ocean Exploration](https://oceanexplorer.noaa.gov/) 的独立知识介绍、影像图注和教育资源。本站中文文字为依据机构资料整理的说明，不复制它们的页面正文。

## 科学口径

每条资料分别记录：

- `displayDepth`：轴上的示意位置，不能作为观测或下潜纪录。海层分组由此位置计算。
- `habitatRange`：仅在所引资料提供适用于条目的数值时填写，必须注明典型分布、类群汇总等适用范围。
- `depthRecord`：文献报告的观测或标签纪录，包含年份、解释和独立出处，与日常栖息范围分开。
- `scientificName`、`taxon`：区分单一物种与属、科等类群。旧 ID 为保持链接和收藏兼容可能与当前中文名不同，例如 `hadal-jellyfish` 现在对应 Atolla 皇冠水母。
- `sources`、`reviewedOn`：条目级机构资料或原始研究，以及整理日期。整理日期不表示原研究发表于当天，也不保证后续纪录没有变化。

海层边界使用常见教学划分，实际光照受海域和水体影响。压力使用 `P = P₀ + ρgh`，固定海水密度 1025 kg/m³ 和重力加速度 9.81 m/s²，输出绝对压力近似值。气囊模型使用等温、固定气体量、内外压力平衡的假设。反照明示范采用相对亮度，不是生物视觉的实测模型。

## 图片维护

49 个生物条目均使用经过主体和许可核对的真实照片，包括机构发布的野外影像、水族馆照片和采集或馆藏标本照片。不使用生成图、绘画、模型照片或来源不明的搜索结果。图片本地保存为 WebP，页面无需连接第三方图片服务器。本次增加尖牙鱼、太平洋蝰鱼、鹈鹕鳗、雪人蟹、庞贝虫、游泳海参、泡泡糖珊瑚、皇带鱼、斑点银鲛、鹦鹉螺、海洋斧头鱼和管水母；类群照片明确注明所拍摄的成员。

`media.ts` 逐张记录原始页面、原图 URL、图片主体学名、拍摄状态、图注、作者、许可及处理说明。类群条目的照片只展示该类群中可确认的种或属，不将照片主体等同于整个类群。野外照片不一定摄于轴上展示的深度；标本外观可能因采集或保存改变，百科会说明。生物卡片和百科保留图片完整边界，避免切掉关键身体部位。图片加载失败时显示文字提示，仍可打开百科。

六幅原知识线稿已移除。海洋雪、活跃热液烟囱、鲸骨群落、海底峡谷陡壁和科考船采用真实影像；马里亚纳海沟采用 NOAA 水深地形数据图，明确标注为数据可视化，不称为海底照片。新影像共约 605 KiB，完整图注在专题文章中，全部出处也可在参考资料页展开。机构网页转载遵循逐图说明和 [NOAA Ocean Exploration 使用要求](https://oceanexplorer.noaa.gov/about/media-kit/)，保留署名；不能以 NOAA 网页域名代替核对第三方版权标注。

图片 URL 携带 `version` 参数，值为本地 WebP 文件 SHA-256 的前 12 位。更换图片时同步更新该值，测试会检查版本与文件内容一致，避免浏览器或 CDN 继续使用旧图片或旧的失败响应。

照片分别遵循来源注明的公有领域、CC BY、CC BY-SA 或其他许可；不能把机构网站的所有图片都视为可转载。管眼鱼照片来自北海道大学综合博物馆（HUMZ 177309，[原始页面](https://minna-museum.jp/data/393)），来源注明 **CC BY-NC**，未给出版本；庞贝虫照片来自 [WoRMS 图库](https://www.marinespecies.org/photogallery.php?album=673&pic=64130)，许可为 **CC BY-NC-SA 4.0**。本站用于非商业科普，商业复用需另行确认。共享许可图片及其缩放、转换或裁切版本保持相同许可，代码许可不替代图片许可。

海沟狮子鱼照片取自原科研图版的 A 面板，保留 5 cm 比例尺；皇冠水母照片裁去部分外围背景并保留长触手。巨型管虫源文件已调整亮度，深海钩虾源文件已有署名的降噪版本。管水母使用 2011 年仅裁切背景的版本。其余图片只做等比例缩放和 WebP 转换，不改变生物外形。

添加条目前应核对对应学名、资料范围与图片主体。不要把极端观测写成典型行为，不要将某个物种的特征套用于整个类群。

## 验证

`npm test` 检查模型、海层边界、唯一 ID、资料字段、全部条目的真实照片记录和本地 WebP 文件、单一物种条目的图文学名一致性、图片署名与许可、展示位置与范围一致性、专题影像及其内容版本、照片与数据图分类、延伸阅读 ID、所有条目的布局完整性、同深度分组、防重叠间距及坐标往返换算。

`npm run test:e2e` 使用桌面和手机两种 Chromium 视口，验证独立页面导航、浏览器历史、图鉴分页与筛选重置、手机菜单 Esc 操作、专题直达与刷新、图注和数据图说明、学名搜索与定位、百科 Esc 关闭及原位恢复、收藏和阅读记录恢复、下潜续读、分享链接、互动实验、内容溢出，以及页面模块、图片或浏览器存储失败时的恢复入口。

游戏规则测试覆盖六种文字结局在两档难度下的可达性、装备与资源限制、存档演算，以及经营游戏两档预算和四种事件顺序的通关、建造连通性、人员上限、考察、维护收支、短缺恢复与失败、评估期限和自由经营。浏览器测试实际操作两款游戏通关、阅读百科、刷新续玩、独立存档、导出导入、错误文件保护、重开确认和存储受限时的导出。
